Normative reference for `GET /v1/network/threat-state` — the [L4 thermometer](/concepts/protection-network#l4-threat-thermometer)'s read of the [L1 cross-tenant aggregator](/concepts/protection-network#l1-cross-tenant-aggregator) state. This is a **public-aggregate disclosure**: the response is the same global cross-tenant snapshot for every caller, not scoped to the caller's own tenant, and rows carry no per-tenant identifiers — only L0 fingerprint slices per axis.

The underlying aggregator table is internal; this spec documents what is on the wire, not the table column list.

## 1. Top-level response shape

```jsonc
{
  "snapshot_at": "<ISO-8601 UTC>",
  "totals": { "calm": 12, "elevated": 1, "high": 0, "under_attack": 0, "total": 13 },
  "by_substrate": [ /* array of bucket state objects, see §2 */ ],
  "by_vertical":  [ /* ... */ ],
  "by_pattern":   [ /* ... */ ],
  "by_source":    [ /* ... */ ]
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `snapshot_at` | string | Yes | ISO-8601 UTC timestamp the aggregation RPC evaluated at. |
| `totals` | object | Yes | Counts across all four axes combined: `calm`, `elevated`, `high`, `under_attack`, `total` (all integers). |
| `by_substrate`, `by_vertical`, `by_pattern`, `by_source` | array | Yes | Array of bucket-state objects (§2) for that axis — the top-`max_buckets` most elevated buckets. May be empty if the axis has no active buckets. |

## 2. Bucket state object

```json
{
  "bucket_value": "<L0 fingerprint slice>",
  "state": "calm",
  "prior_state": null,
  "state_changed_at": "<ISO-8601 UTC>",
  "updated_at": "<ISO-8601 UTC>"
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `bucket_value` | string | Yes | The L0 fingerprint slice identifying this bucket within its axis. Carries no per-tenant identifier — this is a public-aggregate disclosure surface. See §3 for per-axis semantics. |
| `state` | enum | Yes | `"calm" \| "elevated" \| "high" \| "under_attack"`. See §4. |
| `prior_state` | enum or `null` | No | The state before the most recent transition; `null` until the bucket has changed state at least once. |
| `state_changed_at` | string | Yes | ISO-8601 UTC timestamp of the most recent state transition. |
| `updated_at` | string | Yes | ISO-8601 UTC timestamp the rolling-stats roll-up last touched this row (may be more recent than `state_changed_at` even with no state change). |

## 3. Per-axis bucket identifier semantics

The four axes scope cross-tenant aggregation along orthogonal dimensions:

| Axis | Bucket identity | Meaning |
|---|---|---|
| `substrate` | Hash of the [substrate fingerprint](/concepts/substrate-fingerprint) | Aggregates across customers running on the same AI substrate. |
| `vertical` | Vertical-id enum value | Aggregates across customers in the same industry vertical. |
| `pattern` | Canonicalized pattern fingerprint hash | Aggregates across customers seeing the same detection-pattern signature. |
| `source` | Canonicalized source fingerprint hash | Aggregates across customers receiving traffic from the same source identity class. |

Bucket identifiers are opaque to the customer; the customer reads the state, not the bucket's underlying composition. Internal aggregation thresholds and per-bucket state-transition logic are platform-level config — they are not surfaced on the wire.

**Only non-`calm` buckets are enumerated.** Each `by_<axis>` array excludes buckets currently in `calm` state entirely — a bucket only appears once it has transitioned to `elevated` or worse. The count of calm buckets is reflected only in `totals.calm`, never as individual rows. At full baseline (nothing elevated anywhere), every `by_<axis>` array is empty and `totals` carries the calm count with `elevated`/`high`/`under_attack` all zero.

## 4. State enum

| Value | Semantic | Customer-side effect |
|---|---|---|
| `calm` | Baseline; no anomalous cross-tenant signal on this bucket. | No L2 under-attack overlay engaged. |
| `elevated` | Above baseline; one or more cross-tenant signals trending up. | L2 overlay candidate; not yet active. |
| `high` | Sustained cross-tenant pressure on this bucket. | L2 under-attack overlay auto-elevates protection against the customer's [elevation ceiling](/concepts/protection-network#under-attack-ceiling-additive-ratcheting-not-override). |
| `under_attack` | Active cross-tenant campaign confirmed on this bucket. | L2 overlay at maximum elevation; additional integrity-side primitives engage (canaries, frozen credential issuance, full AIP proof rate). |

The state transitions are bidirectional with hysteresis; a bucket that elevates to `high` does not immediately demote to `calm` even when the underlying signal subsides — the aggregator requires sustained low signal across the exit hysteresis window before demotion.

## 5. Query parameters

| Parameter | Type | Default | Notes |
|---|---|---|---|
| `max_buckets` | integer | 10 | Top-N most elevated buckets returned per axis. Clamped to `[1, 50]`. There is no way to filter to a single axis — the response always returns all four `by_<axis>` arrays. |

Per-axis arrays are sorted by severity descending (`under_attack` > `high` > `elevated`), then `state_changed_at` descending within the same severity; truncation to `max_buckets` drops the tail.

**Auth:** any authenticated principal — a Bearer token, an `X-Mnemom-Api-Key`, or (for the dashboard) a session cookie. There is no anonymous access to this endpoint.

## 6. Example — calm-at-GA response

At GA, with the network calm across every bucket, `calm` buckets are excluded from the arrays entirely (per §3) — only `totals.calm` reflects them:

```json
{
  "snapshot_at": "2026-05-30T00:00:00Z",
  "totals": { "calm": 3, "elevated": 0, "high": 0, "under_attack": 0, "total": 3 },
  "by_substrate": [],
  "by_vertical": [],
  "by_pattern": [],
  "by_source": []
}
```

## 7. Example — one bucket elevated (synthetic for documentation)

This example is documentation-only — at GA there is no real elevated bucket. The shape is what the customer sees if the substrate axis registers cross-tenant elevation — note the calm `v-financial-services` bucket does **not** appear in `by_vertical`:

```json
{
  "snapshot_at": "2026-05-30T03:14:30Z",
  "totals": { "calm": 2, "elevated": 1, "high": 0, "under_attack": 0, "total": 3 },
  "by_substrate": [
    {
      "bucket_value": "sb-synthetic-test",
      "state": "elevated",
      "prior_state": "calm",
      "state_changed_at": "2026-05-30T03:14:07Z",
      "updated_at": "2026-05-30T03:14:07Z"
    }
  ],
  "by_vertical": [],
  "by_pattern": [],
  "by_source": []
}
```
