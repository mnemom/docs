# Extend the Docs Internal-Reference Gate to api-reference/endpoint

**ADW ID:** 05d5fdaf
**Date:** 2026-06-25
**Plan-Spec:** N/A

## Overview

The `check-doc-examples.mjs` CI gate previously excluded the entire `api-reference/` directory on the assumption that its pages were auto-generated by Mintlify and would trivially round-trip from `openapi.json`. This change corrects that assumption: while the rendered schema display is auto-generated, the hand-authored curl examples and prose in `api-reference/endpoint/` pages (including reputation endpoints flagged in issue-319) can drift from the live spec. The gate now scans those pages as part of its default scope.

## What Was Built

- Extended the default scan scope to include `api-reference/endpoint` alongside the existing customer-facing directories
- Added a `--self-test` flag that validates scope-resolution logic without requiring a live spec network call
- Added two self-test assertions: (1) that `api-reference/endpoint` is included in the default scope, and (2) that reputation endpoint pages are present within that scope
- Updated the `--help` output to document the new `--self-test` flag

## Technical Implementation

### Files Modified

- `scripts/check-doc-examples.mjs`: Extended default scope constant, added `--self-test` CLI flag and its self-contained test harness, updated help text and CLI argument parsing

### Key Changes

- `DEFAULT_SCOPE` constant extracted from the inline `let scope` initializer to make it referenceable by the self-test block without requiring spec loading
- `api-reference/endpoint` appended to `DEFAULT_SCOPE` — the only scope change; broader `api-reference/` subdirectories (e.g., auto-generated spec display pages) remain excluded
- `SELFTEST` flag parsed early (before the spec network call) so `--self-test` exits before any HTTP request is made, keeping it fast and offline-safe
- Self-test assertion 2 uses the regex `/(^|-)reputation(-|\.)/.test(basename(p))` to match both internal positions (`get-reputation-agent-id.mdx`) and terminal positions (`get-teams-team-id-reputation.mdx`) in endpoint filenames
- `basename` imported from `node:path` to support the self-test filename matching

## How to Use

The gate runs automatically in CI with no changes required. To run it locally:

```bash
# Full scan (now includes api-reference/endpoint)
node scripts/check-doc-examples.mjs

# Verify scope-resolution logic offline (no network call)
node scripts/check-doc-examples.mjs --self-test

# Limit to a specific subdirectory
node scripts/check-doc-examples.mjs --scope api-reference/endpoint
```

## Configuration

The default scope is defined by the `DEFAULT_SCOPE` constant in `scripts/check-doc-examples.mjs`. To override it at runtime, pass `--scope <comma-separated-dirs>`.

The `OPENAPI_SPEC_PATH` environment variable can override the spec URL (see `_load-spec.mjs`) — unchanged by this feature.

## Testing

```bash
# Self-test (offline, no spec required)
node scripts/check-doc-examples.mjs --self-test

# Full lint + type check
npm run lint
```

The self-test exits 0 when both assertions pass, 1 otherwise, making it safe to run in CI as a pre-flight check.

## Notes

- The broader `api-reference/` tree (path/method schema display) remains excluded — only the `endpoint/` subdirectory containing hand-authored pages is added to scope.
- The reputation endpoint coverage was the specific trigger for issue-319; the fix is general and covers all `api-reference/endpoint/` pages going forward.
- Live execution against staging (T5-1.3) remains out of scope for this change.
