# Spec — llms.txt onboarding links (/quickstart, /for-agents entry points)

- **Status:** Done
- **Branch:** feature-issue-249-adw-79ed7794-llms-txt-onboarding-links-quickstart-for
- **Location:** docs.json (redirects)
- **Related docs:** for-agents/index.mdx, quickstart/overview.mdx, AGENTS.md

## Problem / Objective

### Problem Statement

`docs.mnemom.ai/llms.txt` is auto-generated by Mintlify from the `docs.json` navigation tree. Agents discovering Mnemom via `llms.txt` land on canonical page paths such as `/for-agents/index` and `/quickstart/overview`, but the bare entry-point URLs `/for-agents` and `/quickstart` return 404. This breaks the acceptance criteria that onboarding links resolve, and makes the shortest discoverable paths unusable.

The navigation order was already corrected in issue #192 (PR #248): "For AI Agents" is tab 1 and "Getting Started" is tab 2, so the `llms.txt` listing already surfaces these pages near the top. The remaining gap is that the bare paths do not redirect to the canonical first page of each tab.

### Root Cause Analysis

Mintlify exposes pages under their full slug (e.g. `/for-agents/index`, `/quickstart/overview`). Without explicit redirects, the shorter canonical forms `/for-agents` and `/quickstart` resolve to 404. The French and Spanish locales already have working redirects (`/fr/quickstart` → `/fr/quickstart/overview`, `/es/quickstart` → `/es/quickstart/overview`), but the English locale did not.

## Approach & Changes

Add two redirects to `docs.json` so the bare onboarding entry-point URLs resolve:

- `/quickstart` → `/quickstart/overview`
- `/for-agents` → `/for-agents/index`

These are the only changes needed. The navigation order (For AI Agents → Getting Started as tabs 1 and 2) was already correct, so `llms.txt` already surfaces the right pages near the top. The redirects simply make the bare paths resolve, satisfying the "links verified to resolve" acceptance criterion.
