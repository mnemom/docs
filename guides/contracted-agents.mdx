A contracted agent works from GitHub issues instead of your terminal. You file an issue and label it `mnemom`. Mnemom checks the request, seals it as a contract and starts a job. An agent does the work and opens a PR. The [Mnemom record](/guides/record-setup) check on that PR shows the sealed contract.

<Note>
Contracted agents build on [durable sessions](/gateway/durable-sessions). Mnemom durable agent and Mnemom contracted agents come with the Durable agent invite tier, enabled per Mnemom org by invitation. Ask for access at [mnemom.ai/waitlist](https://www.mnemom.ai/waitlist?interest=durable-agent). `setup contracted` checks this first. The server runner needs the experimental `dispatch` feature. It may change or be removed with no deprecation period.
</Note>

## Set up a repo

```bash
mnemom agent setup contracted <owner/repo>
```

It prints its steps, then does the ones still to do. A re-run picks up where it left off. `--dry-run` prints the first screen and changes nothing. `--json` prints the plan and outcome as JSON and never prompts.

With the default runner (your CI), the steps are:

1. **Durable.** Checks that durable sessions are on for your org and turns the Mnemom record on.
2. **GitHub App.** Checks that the Mnemom Record App is installed on the repo. If not, it prints the install link and waits. `--app <slug>` names a different App.
3. **Model key.** Checks that the repo has an `ANTHROPIC_API_KEY` secret (by name only, never the value). If not, it takes the key from `$ANTHROPIC_API_KEY` or a hidden prompt. It also gives the same key to Mnemom for the intake check.
4. **Turn on.** Switches the repo on with Mnemom.
5. **Runner.** Checks that GitHub Actions is on, then opens a PR that adds the runner workflow and merges it. `--branch <name>` sets the PR branch (default `mnemom/record-enable`).

If the runner PR is not merged yet, setup tells you to merge it before you file an issue.

The runner step writes `.github/workflows/mnemom-agent-run.yml`, so your GitHub CLI login needs the `workflow` scope. A plain `gh auth login` does not include it, and GitHub then answers the write with `404 Not Found`. Add the scope once before you run setup:

```bash
gh auth refresh -h github.com -s workflow
```

If `GH_TOKEN` or `GITHUB_TOKEN` is set, `gh auth refresh` cannot change it: give that token permission to write workflow files (fine-grained token: **Workflows** read and write; classic token: the `workflow` scope). `mnemom record enable` writes the same workflow and needs the same scope.

### Set up without a browser

Setup can run on a machine with no browser or terminal, such as CI or a server:

- **Sign in with an API key.** Set `MNEMOM_API_KEY`. Setup uses the key's own org. An org you selected earlier on this machine still wins.
- **Name the agent.** Set `MNEMOM_AGENT` to an agent your org already has. The agent step needs it, because an API key has no login email to name the agent from.
- **Prove you administer the repo.** Where setup would ask you to approve through GitHub in your browser, it uses `MNEMOM_GITHUB_TOKEN`, else `GH_TOKEN`, instead. Use a GitHub token of a repo admin. Setup never uses `GITHUB_TOKEN`: inside GitHub Actions that is the workflow's own token, which cannot show that a person administers the repo. The token is used for that one check and is not stored.

In a terminal with neither token set, setup asks you to approve in your browser, as before.

## Start a job from an issue

Label an issue `mnemom` to start. Without the label, opening or editing an issue does nothing. If the repo has no `mnemom` label yet, create it once:

```bash
gh label create mnemom --repo <owner/repo> --description "Work for the contracted Mnemom agent"
```

Mnemom checks the request, seals it as a contract and starts a job. If the request is not clear enough, Mnemom sends it back with a comment, and you edit the issue to answer.

The job opens a PR against the default branch and keeps working on it as you review. The PR gets a **Mnemom record** check that shows the sealed contract.

[Hand an issue to the contracted agent](/guides/contracted-agent-issues) covers how to write an issue that seals the first time, the optional limits block, and what the agent does on its PR.

## Runners

Every job runs on exactly one runner. The repo has a default, and a single job can use another.

| Runner | Set up with | Where it runs | Time limit per job |
|---|---|---|---|
| CI (default) | `setup contracted <repo>` | GitHub Actions in your repo | 6 hours |
| Server | `setup contracted <repo> --runner server` | Your own machine | None |
| Mnemom-hosted (experimental) | `setup contracted <repo> --hosted` | Mnemom's infrastructure | Set by Mnemom per run |

### CI

The runner is a GitHub Actions workflow that setup adds to the repo. It runs only on the default branch, is started by Mnemom, and needs the `ANTHROPIC_API_KEY` repo secret.

A job can run for up to **6 hours** (`timeout-minutes: 360`). This is GitHub's hard limit for a job. The key the job gets from Mnemom also lasts 6 hours.

The Actions minutes are your own.

### Server

With `--runner server`, jobs wait for a runner on your own machine:

```bash
mnemom experimental enable dispatch
MNEMOM_EXECUTOR_KEY=<key> mnemom agent run --watch
```

`mnemom agent run --once` runs a single job and exits.

- A server job waits for a runner with no timeout, and it does not fall back to another runner.
- `mnemom agent sessions` and `mnemom agent show` say why a waiting server job waits: no runner is enrolled for the repo, or no runner has claimed the job yet. A `fix:` line gives the command to run. With `--json`, the reason is in `waiting_reason`.
- The job's transcript stays on your machine. The two newest are kept.
- A re-run of setup without `--runner` keeps the repo on the server runner. To move it back to CI, pass `--runner ci`.

### Revoke a server runner

If a runner machine is lost or its key leaks, revoke it from any machine signed in as the person who enrolled it:

```bash
mnemom agent runner list                      # the runners you enrolled, with their grant; this machine's is marked
mnemom agent runner revoke <executor-id>      # the id from the list, or its first 8 or more characters
mnemom agent runner revoke --this-machine     # this machine's own runner
```

- The runner's key stops working at once, so it claims no more jobs.
- Locked durable sessions the runner held are parked. The command says how many.
- Only the person who enrolled a runner can revoke it. Anyone else gets the same answer as for an unknown id.
- Revoking a runner that is already revoked changes nothing.
- If the command reports a server or network error, the runner may still be live. Run it again.
- To enroll the same machine again: `mnemom agent runner enroll --force`.

Both commands take `--json`.

### Mnemom-hosted (experimental)

<Note>
The Mnemom-hosted runner is experimental. It is open to invited orgs, and each org can run only a capped number of hosted jobs at once.
</Note>

With `--hosted`, Mnemom runs the jobs. There is no workflow PR, no repo secret and no machine to keep running.

```bash
mnemom agent setup contracted <owner/repo> --hosted
```

The steps:

1. **Hosted.** Confirms through GitHub that you administer the repo: you enter a code in your browser. The repo then switches to the hosted runner. You need admin or maintain on the repo, and the Mnemom Record App installed on it.
2. **Model key.** Checks that an Anthropic key is stored for your org. If not, it reads one from a hidden prompt, or from stdin with `--model-key-stdin`. The key is stored encrypted at Mnemom. It pays for the intake check and for hosted runs, billed to you by Anthropic.

`--json` cannot finish the GitHub step, so run setup once in a terminal. With no active org, setup uses your only team org. If you belong to several, it stops and asks you to run `mnemom org use <slug>`.

- A hosted job needs a Mnemom balance. With none left, the job ends instead of starting.
- When your org already has as many hosted jobs running as its cap allows, a new job waits and starts when one finishes. To raise your org's cap, email [support@mnemom.ai](mailto:support@mnemom.ai).
- A re-run of setup with neither flag keeps the repo hosted. To leave hosted, pass `--runner ci` or `--runner server`.
- If setup says the hosted runner is not turned on yet, it is not open to your org. Use CI or a server runner.

## Run one job on a different runner

`mnemom agent fuel` seals a batch of contracts in one confirmation. `--runner ci|server|hosted` runs that batch's jobs on the runner you name. Without it, they use the repo's default.

```bash
mnemom experimental enable fuel
mnemom agent fuel <file> --runner server
```

## What it costs

You pay Anthropic directly for the model. Your Anthropic key pays for the intake check and for the agent's work. CI jobs also use your own GitHub Actions minutes. Hosted jobs draw on your Mnemom balance. Contracted agents are not a plan tier.

## Turn a repo off

```bash
mnemom agent setup contracted <owner/repo> --off
```

New issues on the repo are no longer sealed as contracts. GitHub is left as it is: the runner workflow and the Record App stay. Run setup again without `--off` to turn the repo back on.
