# OWASP Agentic Top 10 mapping

Safe House enforces eight named threat patterns at the Mnemom gateway. Buyers evaluating agentic security posture against the **OWASP Top 10 for Agentic Applications** (December 2025, ASI01–ASI10) need a published cross-reference to make the shipped enforcement legible. This page provides that cross-reference.

The discipline is the same one applied throughout this documentation: where Safe House covers an OWASP threat class, the coverage mechanism is named. Where coverage is partial or absent, the gap is stated.

---

## Safe House threat patterns

Safe House detects eight threat categories via its L1 pattern library, L2 LLM analysis layer, and L3 session model. Each pattern has a stable `threat_type` identifier used in API responses, webhook events, and threshold configuration:

| Pattern | `threat_type` | Checkpoint |
|---|---|---|
| Business Email Compromise | `bec_fraud` | Front door |
| Prompt injection | `prompt_injection` | Front door |
| Indirect injection | `indirect_injection` | Front door |
| Social engineering | `social_engineering` | Front door |
| Agent spoofing | `agent_spoofing` | Front door |
| Multi-turn hijack | `hijack_attempt` | Front door (L3 session model) |
| Data exfiltration | `data_exfiltration` | Back door |
| Privilege escalation | `privilege_escalation` | Front door + back door |

## Pattern-to-OWASP mapping

Each Safe House pattern maps to one or more OWASP ASI entries. A pattern can map to multiple entries because OWASP threat classes are defined by attacker goal; Safe House detects by observable signal.

| Safe House pattern | OWASP entry | Coverage level | Enforcement mechanism |
|---|---|---|---|
| `prompt_injection` | **ASI01** Prompt Injection | Full — direct variant | L1 regex families (override phrases, role reassignment, jailbreak openers, authority spoofing); L2 compound confidence scoring; L3 session model |
| `indirect_injection` | **ASI01** Prompt Injection | Partial — indirect variant | L1 instruction-delimiter detection; MinHash similarity against known payloads; L2 instruction-structure detection in tool results. Novel payloads with no similarity to known patterns score lower — see [limits](#gaps-and-limits) |
| `bec_fraud` | **ASI01** Prompt Injection, **ASI05** Agent Impersonation | Full — conjunction detection | Requires co-occurring: financial action term + authority claim + urgency marker + secrecy instruction. Authority framing maps to ASI05 impersonation signal |
| `social_engineering` | **ASI01** Prompt Injection | Full | Authority + urgency signal pair, absent financial action component. Regulatory threat framing, role authority claims, urgency escalation |
| `agent_spoofing` | **ASI05** Agent Impersonation | Full | Claims of override authority or elevated permissions arriving as runtime messages; fake admin agent identifiers; credential presentation patterns in message content |
| `hijack_attempt` | **ASI08** Task Hijacking | Full | L3 session model: topic coherence tracking, escalating action scope, identity drift, pivot detection after trust-building sequence. Threshold: ≥ 0.7 confidence |
| `data_exfiltration` | **ASI09** Sensitive Data Exfiltration | Full | Back-door checkpoint: external destination patterns vs. declared `bounded_actions`, bulk data request language, covert channel patterns. Also enforced independently by Policy Engine |
| `privilege_escalation` | **ASI03** Privilege Compromise | Full | Runtime permission claims; requests outside declared `bounded_actions`; attempts to disable safety mechanisms mid-session. Front-door detection + Policy Engine independent check |

## OWASP-to-coverage mapping

The reverse view — starting from each OWASP entry and tracing what ships in enforcement:

| OWASP entry | Safe House pattern | Additional coverage | Status |
|---|---|---|---|
| **ASI01** Prompt Injection | `prompt_injection`, `indirect_injection`, `bec_fraud`, `social_engineering` | — | **Shipped.** Direct injection fully covered. Indirect injection partial — novel payloads with no payload-library similarity may score below block threshold |
| **ASI02** Malicious Tool Execution | — | Policy Engine: `bounded_actions` enforcement, forbidden-rule Managed Rules, tool capability mappings | **Covered by policy layer, not a Safe House pattern.** Tool execution is constrained before it reaches Safe House's inbound screen |
| **ASI03** Privilege Compromise | `privilege_escalation` | AAP alignment cards declare autonomy envelope; CLPI policy engine enforces | **Shipped.** Runtime privilege claims blocked at front door. Declared envelope enforced at policy layer |
| **ASI04** Memory Poisoning | — | — | **Gap.** Persistent memory store attacks are not in the shipped Safe House pattern library. Defense-in-depth via AIP thinking-block analysis and AAP drift detection provides partial observability of downstream effects, but not upstream interception |
| **ASI05** Agent Impersonation | `agent_spoofing`, `bec_fraud` (authority signal) | — | **Shipped.** Runtime authority claims from inbound messages treated as suspicious by design. Legitimate agent-to-agent authority must be encoded in alignment cards at configuration time |
| **ASI06** Agentic Supply Chain Compromise | — | AEGIS substrate fingerprinting + L1 cross-tenant aggregator | **Covered at AEGIS layer, not Safe House patterns.** Runtime-behavior deviation consistent with supply-chain compromise is detected cross-tenant. Does not replace package-layer provenance — see [supply-chain trust](/guides/supply-chain-trust) |
| **ASI07** System-Prompt Leakage | — | Safe House back-door checkpoint: PII patterns, system-prompt content patterns, alignment-card violation screening | **Covered by back-door checkpoint, no named Safe House pattern.** Outbound screening fires on content that matches system-prompt disclosure patterns. Not a discrete `threat_type` — fires under alignment-card violation classification |
| **ASI08** Task Hijacking | `hijack_attempt` | — | **Shipped.** Session model tracks multi-turn behavioral trajectories. Sudden pivot after N benign turns escalates session risk score. At ≥ 0.7 confidence, routes to human review rather than autonomous block — see calibration note below |
| **ASI09** Sensitive Data Exfiltration | `data_exfiltration` | Policy Engine: `bounded_actions` independent check | **Shipped.** Back-door checkpoint detects external destination routing and bulk data language. Policy Engine provides a second independent enforcement layer |
| **ASI10** Excessive Agency | — | Policy Engine: `bounded_actions` declaration and enforcement; CLPI lifecycle governance | **Covered at policy layer, not a Safe House pattern.** Agents declare their authorized action envelope in alignment cards. The Policy Engine enforces declared scope; Safe House screens for escalation attempts. The boundary between ASI03 and ASI10 in practice: ASI10 is the structural over-permissioning risk (card design), ASI03 is the runtime exploitation of it |

## Gaps and limits

### ASI04 — Memory Poisoning

No shipped Safe House pattern targets memory store attacks. An attacker who can write to an agent's persistent memory — conversation history, vector store, retrieved documents — can influence future turns without a detectable inbound signal. The AIP thinking-block analysis layer provides partial mitigation: if the poisoned memory causes the agent to reason in ways inconsistent with its alignment card, AIP may flag it before the action lands. That is detection of downstream effect, not upstream interception.

**Recommended defense-in-depth:** treat memory stores as an untrusted input boundary, apply the same L1/L2 screening to memory-retrieved content as to external tool results, and enable AIP to catch reasoning anomalies that poisoned memory produces.

### ASI01 indirect injection — novel payloads

Indirect injection via tool results is partially covered. MinHash similarity matching compares tool results against a library of known injection payloads. Sufficiently novel payloads that bear no structural or semantic similarity to known patterns will score below L1 thresholds. L2 analysis provides a second pass, but detection accuracy is bounded by the analysis model's capability.

The arena flywheel closes this gap over time: canary credentials and cross-agent campaign detection surface novel attack infrastructure, and confirmed patterns promote to active detection. For high-sensitivity environments, consider adding application-layer validation of tool results before they re-enter the agent context.

### ASI08 — human escalation at default threshold

The `hijack_attempt` pattern routes to human review (not autonomous block) at the default 0.7 confidence threshold. This is intentional — legitimate multi-topic conversations produce similar L3 signals. If your use case can tolerate more aggressive autonomous blocking, lower the `hijack_attempt` threshold in the [protection card](/concepts/protection-card).

## Pairing Safe House with application-layer controls

OWASP guidance recommends pairing runtime substrate controls with application-layer controls. For the gaps above:

- **ASI04 (Memory Poisoning):** Apply Safe House's inbound screening to memory-retrieved content as well as direct inbound messages. This is not the default — configure the SDK to route memory fetches through the Safe House evaluation layer.
- **ASI06 (Supply Chain):** AEGIS covers the runtime-behavior dimension. Pair with SLSA/Sigstore package provenance for the build-time dimension. See [supply-chain trust](/guides/supply-chain-trust).
- **ASI10 (Excessive Agency):** Card design is the primary defense. Scope `bounded_actions` as narrowly as the agent's function permits; CLPI enforces declared scope. Safe House screens for runtime escalation attempts (ASI03), but structural over-permissioning is a card design issue.
